١. مسارات النسخة الجديدة

تُحفظ قاعدة البيانات داخل %APPDATA%\MOO3DSTUDIO، والنسخ الاحتياطية داخل Documents/MOO3DSTUDIO/Backups. لو بتثبّت البرنامج لأول مرة، أضف خاماتك وأسعارها وأوزانها الحقيقية من شاشة الخامات.

راجع نموذج Bambu Lab A1 والأصل الافتراضي (٦٠٬٠٠٠ جنيه / ٥٬٠٠٠ ساعة)، وتأكد إن تكلفة التشغيل والكهرباء والصيانة مناسبة لشغلك قبل اعتماد الأسعار.

٢. استخراج ملف تثبيت Windows بدون كتابة كود

الطريقة الأولى: GitHub Desktop ثم Actions

  1. فك ضغط الحزمة. ادخل المجلد الذي يحتوي على package.json وmain.js وSTART-HERE.html.
  2. في GitHub Desktop اختر File → Clone repository → URL، والصق https://github.com/Ms-Studio-3d/MOO3DSTUDIO واختر مجلدًا محليًا جديدًا.
  3. انسخ محتويات الحزمة المفكوكة إلى جذر المجلد المستنسخ حتى يظهر package.json بجانب js و.github. لو رفعت الملفات القديمة بالفعل، اختر استبدال الملفات المتطابقة داخل المجلد المستنسخ الجديد.
  4. في GitHub Desktop اكتب Update MOO3D Farm في خانة Summary، واضغط Commit to main ثم Push origin أو Publish branch. تأكد إن .github/workflows/build-clean.yml ظهر على GitHub.
  5. اذهب إلى Actions → Build Windows Installer. قد يبدأ تلقائيًا بعد الحفظ على main. ويمكن تشغيله يدويًا من Run workflow واختيار الفرع الذي رفعت إليه الملفات.
  6. بعد ظهور علامة النجاح الخضراء، افتح نتيجة التشغيل، ثم قسم Artifacts، وحمّل MOO3DSTUDIO-Windows-Installer. فك ضغطه للحصول على ملف MOO3D Farm-Setup-0.0.4.exe.

إن ظهر فشل أحمر، لا تستخدم نتيجة تشغيل قديمة على أنها الإصدار الجديد. افتح الخطوة الفاشلة واحتفظ برسالة الخطأ. سير البناء مهيأ لإيقاف العملية إذا فشلت الاختبارات أو تحميل SQLite داخل Electron.

الطريقة الثانية: من جهاز Windows

هذه الطريقة تتطلب Node.js 22.12 أو أحدث واتصال إنترنت لتنزيل الاعتمادات. بعد تثبيته من الموقع الرسمي، فك الحزمة كاملة واضغط مرتين على BUILD-WINDOWS.cmd. لا تحتاج كتابة أو تعديل كود.

اترك النافذة مفتوحة حتى تنتهي. السكربت ينزل الاعتمادات، ويشغّل الاختبارات، ويجهز SQLite لـElectron، ثم يبني المثبت. عند النجاح يفتح مجلد dist. عند الفشل يفتح build-windows.log بدل الاستمرار بتثبيت غير مكتمل. تنزيل الاعتمادات وبناء مثبت Windows لم يُنفذا في بيئة تسليم هذه الحزمة، لذلك يلزم تحقق النتيجة على جهازك.

٣. ما الذي اتصلح؟

زر × بجانب الخامة يشيلها من الأوردر الحالي ويعيد الحساب، ويحتفظ بالجرامات المكتوبة للخامات الباقية. الخامة تفضل موجودة في المخزون وتقدر تختارها تاني.

تعديل وحذف البيعة من المبيعات، ظهور رسائل الخطأ فوق النوافذ، الحفاظ على تكاليف البيعة القديمة عند تعديل بياناتها فقط، وتحديث أرقام المبيعات والكاش بعد الحفظ. كذلك إنشاء خامة من المشتريات، واسترجاع النسخ التي تحتوي على خامات مرتجعة أو كميات أكبر من وزن البكرة المرجعي، وحفظ نسخة أمان قبل الاستيراد.

الفاتورة أصبحت نسخة عميل لا تعرض تكلفة الإنتاج أو الربح أو الملاحظات الداخلية. وإعادة فتح قاعدة بيانات فارغة عمدًا لم تعد تعيد الخامات والأصول الافتراضية المحذوفة.

طريقة الحساب محفوظة: محرك التسعير ودوال الحساب الأصلية تم التحقق منها ببصمة SHA-256. لم تتغير نسب الربح أو التقريب أو معادلات الكهرباء والصيانة والإهلاك. حذف الأصول أو تغيير أسعار الخامات يغير قيم المدخلات بطبيعة الحال، وليس المعادلة.

٤. تصفير المبيعات والخامات والبدء من جديد

بعد تثبيت الإصدار الجديد افتح الإعدادات ← بداية جديدة / تصفير البيانات. اقرأ نطاق المسح، واكتب بداية جديدة في خانة التأكيد، ثم اضغط حفظ نسخة أمان ثم بدء صفحة جديدة. ستظهر نافذة تأكيد ثانية؛ الإلغاء لا يمسح شيئًا.

البندالسلوك الافتراضي
كل المبيعات والأوردرات والعروض والمشتريات والخامات وحركاتهاتُمسح بالكامل، وليس نتائج البحث فقط.
إجمالي المبيعات والأرباح وعدد الطلبات وكاش البدايةتبدأ من صفر؛ بعدها أدخل رصيد الكاش الحقيقي.
أسماء العملاءمشتقة من الأوردرات؛ تزول بزوال الأوردرات.
الطابعات والأصول وإعدادات التسعيرتظل كما هي. حذف الطابعات أو الأصول اختيار إضافي غير محدد افتراضيًا.
إجمالي ساعات الماكينة وآخر صيانةيتم الحفاظ عليها؛ ساعات المبيعات القديمة تُنقل إلى ساعات البداية. التصفير الكامل له اختيار مستقل.
تسلسل أرقام الأوردرات والعروضيستمر ولا يبدأ تلقائيًا من جديد. اختيار مستقل يسمح بالبدء من ORD-1001 / Q-1001 للبيانات التجريبية فقط.

للحفاظ على نفس مدخلات التسعير: اترك اختياري حذف الطابعات والأصول غير محددين. يمكن مسح الخامات وإضافة مخزونك الحقيقي دون مسح الأصول.

قبل المسح تُكتب نسخة مؤكدة في Documents/MOO3DSTUDIO/Backups/Protected. إذا فشل حفظ النسخة تتوقف العملية قبل المسح. هذه النسخ المحمية لا تُحذف ضمن تدوير آخر عشر نسخ تلقائية؛ راقب مساحة القرص وانسخ المهم إلى مكان خارجي.

بعد النجاح يظهر مكان الملف كاملًا. زر فتح مجلد نسخ الأمان يوصلك إليه. لاستعادة البيانات السابقة استخدم الإعدادات ← استيراد Backup واختر ملف ما قبل التصفير. الاستيراد يستبدل البيانات الحالية؛ لا يدمجها مع شغل أدخلته بعد ذلك.

٥. تجربة القبول قبل أول يوم شغل

  1. أضف خامتين للأوردر واكتب وزنًا لكل واحدة. اضغط × بجانب الخامة الثانية وتأكد إن الصف اختفى والسعر اتحدث والوزن الأول فضل زي ما هو.
  2. استخدم بيانات تجريبية، واجعل رصيد خامة ١٠٠٠ جرام. سجل بيعة تستخدم ١٠٠ جرام. ينبغي أن يبقى ٩٠٠ جرام وأن تظهر البيعة في المبيعات ويتحدث الـDashboard.
  3. من المبيعات اضغط تعديل، وغير اسم العميل فقط ثم احفظ. ينبغي أن يظل المخزون ٩٠٠ جرام والسعر والتكلفة والربح كما كانوا. اقفل البرنامج وافتحه وتحقق من استمرار التعديل.
  4. احذف البيعة التجريبية. ينبغي أن تختفي ويرجع الرصيد ١٠٠٠ جرام مرة واحدة فقط. اختبر أيضًا تصدير نسخة واسترجاعها قبل إدخال بيانات مهمة.
  5. جرّب التصفير على البيانات التجريبية، ثم اقفل البرنامج وافتحه: الخامات ينبغي أن تظل فارغة. أدخل مخزونك وكاش البداية الحقيقيين، وراجع الطابعات والأصول قبل العمل.
مهم بخصوص الحذف: حذف البيعة هنا يصحح تسجيلًا خاطئًا ويرجع خاماتها للمخزون. لا تستخدمه لمرتجع عميل لقطعة طُبعت بالفعل؛ الخامة المستهلكة فعليًا لا ترجع بكرة خام بمجرد حذف الفاتورة.

٦. حدود النسخة والاختبارات

يشغّل سير البناء اختبارات التسعير، وإزالة الخامات، والمخزون، واستعادة النسخ الاحتياطية، وبدء التشغيل بقاعدة فارغة.

لم يُختبر هنا ملف تثبيت Windows أو النوافذ الأصلية للنظام أو الطباعة الفعلية. اختبارات الواجهة استخدمت بديلًا تجريبيًا لنافذة التأكيد، واختبارات SQLite استخدمت مشغل Node المتوافق الموجود أصلًا في المشروع. اختبار Electron/SQLite الأصلي مضاف إلى مسار بناء Windows ليعمل هناك.

هذه ليست إعادة بناء لكل سياسات البرنامج: الدفع الكامل الكاش وحالة الأوردر الأولية كما في المصدر القديم. الهالك الإضافي يحتفظ بطريقة تسعيره الحالية؛ خصم المخزون ما زال يعتمد على صفوف استهلاك الخامات ولا يوزع الهالك الإضافي تلقائيًا. تحديث Electron والأمان الشامل وربط الطابعات الفعلية خارج نطاق هذا الإصلاح.
